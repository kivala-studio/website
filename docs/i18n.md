# Internationalisation

## Locales and URLs

- Locales: `pt` (default) and `en` (`src/i18n/routing.ts`).
- `localePrefix: "as-needed"`: Portuguese pages have no prefix, English pages are under `/en`. Slugs are Portuguese in both languages.
- The next-intl middleware runs inside the proxy (`src/proxy.ts`). Its locale detection is at next-intl's defaults; a Playwright comment records that a browser preferring English is sent to `/en` (`tests/e2e/design.spec.ts`).
- `<html lang>` is `pt-AO` or `en-AO` (`src/app/[locale]/layout.tsx`). News articles are marked `lang="pt-AO"` in both languages (`ARTICLE_LANGUAGE` in `src/domain/news/article.ts`).
- The time zone given to next-intl is `Africa/Luanda` (`src/i18n/request.ts`).
- Language is changed by a link to the same page in the other locale (`src/features/site/language-switch.tsx`, `src/features/settings/language-choice.tsx`).
- Route handlers that redirect take the locale from a form field or from the path (`localeOf`, `localeOfPath`).

## Message catalogue

- `messages/pt.json` and `messages/en.json`, nested by dotted key, in ICU format.
- `npm run messages` runs `scripts/convert-messages.mjs`, which converts the iOS string catalogue `Localizable.xcstrings` into both files. Its default input path is `../.reference/ios/Invest.AO/Resources/Localizable.xcstrings`, or the path given as the first argument.
  - `%@`, `%lld` and positional arguments become `{arg1}`, `{arg2}`, ….
  - A dotted iOS key that is also a prefix of other keys becomes `<key>.label`.
  - Keys that are sentences are renamed to `legacy.<camelCaseName>`.
  - Format-only keys are dropped.
  - `messages/key-map.json` records every rename (414) and drop (24).
  - A language without a value falls back to the Portuguese value, then to the key.
- The `site` namespace is web-only (marketing, legal, SEO, plans). The converter preserves it and fails if the iOS catalogue uses that name.
- `messages/messages.test.ts` checks that both languages have the same keys, that each message uses the same arguments in both, and that every message parses and renders.

## Client messages

The whole catalogue is available to server components. Client components receive a subset, to keep HTML small (`src/i18n/client-messages.ts`):

- Every page ships the namespaces in `CLIENT_NAMESPACES` (`common`, `components`, `designSystem`, `errors`, `formatting`, `market`, `site`) plus the single keys in `CLIENT_KEYS`.
- An area adds its own keys with `<AreaMessages area="…">` (`src/i18n/area-messages.tsx`, `src/i18n/scoped-messages.tsx`). Areas: `market`, `app`, `news`, `learn`, `simulation`, `unusualActivity`, `weekAhead`, `share`, `plans`, `auth`, `setup` (`AREA_KEYS`).
- A client component that starts using a new key needs that key added to `CLIENT_NAMESPACES`, `CLIENT_KEYS` or its area in `AREA_KEYS`. `src/i18n/client-messages.test.ts` tests the selection.
- The gallery page passes the whole catalogue (`src/app/[locale]/dev/design/page.dev.tsx`).

## Links and navigation

`src/i18n/navigation.ts` exports next-intl's `redirect`, `usePathname`, `useRouter`, `getPathname` and the app's own `Link` (`src/i18n/link.tsx`). `Link` adds:

- `prefetch="intent"`: no viewport prefetch; the route is prefetched once the pointer rests on the link, a finger touches it or it gains focus.
- A pending marker, so navigation groups mark the destination as current while its page loads.

## Formatting

next-intl resolves messages only. Numbers, money and dates are formatted by `src/domain/format`:

- `pt` formats as pt_AO and `en` as en_AO; the region is always Angola.
- pt_AO puts the currency symbol after the amount and groups from four digits with a no-break space; en_AO follows `en`.
- Rounding is half-even on `Decimal`, without passing through a binary float.
- Percentages are percentage points (4.32 means 4,32 %).
- Dates are read in `Africa/Luanda` (UTC+1 all year). Civil dates are `YYYY-MM-DD` strings.
- `createFormat(locale, translate)` builds the formatter on the server; `useFormat` (`src/ui/format.ts`) in client components.
- A formatter table is checked in each browser engine by the Playwright test tagged `@engines` in `tests/e2e/design.spec.ts`.

## Copy

Portuguese copy addresses the reader as "tu" in the `site` namespace (for example `site.auth.noBankLink`: "Não liga a tua conta bancária ou de corretagem."). Strings outside `site` are the iOS catalogue's wording as converted.
